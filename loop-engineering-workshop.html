STEP 2

하네스를 만들게 한다

아래 명세를 AI 도구에 붙여넣어 miniloop.py를 받고, 나는 검수만 합니다.

2-1생성 프롬프트를 붙여넣는다

아래 명세대로 miniloop.py 하나를 만들어라. Python 표준 라이브러리만 쓰고, 파일 하나로 끝낸다.

[과제]
회의록에서 나온 지저분한 액션 아이템 한 줄을 정리된 한 줄로 바꾼다.
예: "  [ ] 배포 스크립트 고치기 @민수 ASAP  " → "@민수 배포 스크립트 고치기"

[파일]
- tasks.json : 같은 폴더에 이미 있다. {"id","split","input","expected"} 목록.
               split은 "train" 6개, "heldout" 4개.
- prompt.txt : 같은 폴더에 이미 있다. 지시서. 규칙 이름 한 줄에 하나.

[규칙 사전: prompt.txt에 나올 수 있는 전체 목록]
지시서에 적힌 규칙만 적용한다. 적용 순서는 파일의 줄 순서와 무관하게 아래 순서로 고정한다.
1. strip-checkbox : 앞쪽 공백과 "[ ]"/"[x]" 마커를 제거한다. 마커 뒤 공백은 남긴다.
2. drop-urgency   : "!" 문자를 모두 지우고, "ASAP"/"급함"/"빨리"와 정확히 일치하는
                    토큰(공백 기준)을 제거한다. 남는 공백은 그대로 둔다.
3. assignee-first : "@"로 시작하는 첫 토큰을 문장 맨 앞으로 옮기고 뒤에 공백 하나를 둔다.
                    나머지 텍스트는 글자 그대로 둔다.
4. collapse-spaces: 연속 공백을 하나로 줄이고 앞뒤 공백을 제거한다.

[명령 세 개]
- run   : train 사례를 지시서대로 변환해 expected와 비교한다.
          {"split": "train", "score": 0.333, "passed": 2, "total": 6} 형태로 출력.
          사례마다 한 줄씩 trace.jsonl에 append한다 (id, input, expected, got, pass).
- trace : trace.jsonl의 마지막 run 기준으로, 실패한 사례만 "입력/기대/실제"를 나란히 보여준다.
- gate  : --candidate <파일> 로 받은 새 지시서를 heldout으로만 채점해, 현재 prompt.txt
          점수보다 높을 때만 accept하고 prompt.txt를 그 내용으로 덮어쓴다. 아니면 reject.
          {"verdict": "accept", "current": 0.25, "candidate": 1.0} 형태로 출력.

[불변식: 어기면 다시 만들게 한다]
1. gate는 heldout만 채점한다. train을 쓰지 않고, trace.jsonl에도 쓰지 않는다.
2. 같은 입력이면 항상 같은 점수. 판정에 타임스탬프·난수·네트워크가 끼면 안 된다.
3. 모든 파일 입출력은 encoding="utf-8"로 한다. Windows에서 한글이 깨지지 않게.

2-2인수 검사: 둘만 본다

검사 ① 눈으로: miniloop.py를 열어 gate 부분을 봅니다. heldout만 읽으면 통과. train이 섞여 있으면 에이전트에게 "불변식 1을 어겼다. gate가 heldout만 채점하게 고쳐라"라고 시킵니다.

검사 ② 명령으로: 같은 명령을 두 번 쳐서 완전히 같은 출력이 나오는지 봅니다.

python3 miniloop.py run
python3 miniloop.py run
python miniloop.py run
python miniloop.py run

기대 출력: 두 번 다 정확히 이 줄

{"split": "train", "score": 0.333, "passed": 2, "total": 6}
{"split": "train", "score": 0.333, "passed": 2, "total": 6}
막혔을 때: 0.333이 아니다

대개 규칙을 파일 줄 순서대로 적용한 구현입니다. 에이전트에게 "규칙 적용 순서를 명세의 고정 순서(strip-checkbox → drop-urgency → assignee-first → collapse-spaces)로 고쳐라"라고 시키고 다시 돌립니다.

두 번의 출력이 서로 다르면 불변식 2 위반입니다. "판정에서 비결정적 요소를 빼라"라고 시킵니다.

체크포인트: 같은 0.333이 두 번 나오면 STEP 2 끝. 과제가 바뀌어도 이 두 검사는 그대로 씁니다.

3-3EDIT지시서에 규칙 한 줄을 더한다

규칙 사전에 있던 drop-urgency가 정확히 이 실패를 막습니다. 원본은 두고 후보 파일을 만듭니다.

cp prompt.txt prompt.better.txt
echo "drop-urgency" >> prompt.better.txt
Copy-Item prompt.txt prompt.better.txt
Add-Content prompt.better.txt "drop-urgency"

3-4GATE게이트로 판정한다

게이트는 이 후보를 heldout 4건으로만 채점합니다.

python3 miniloop.py gate --candidate prompt.better.txt
python miniloop.py gate --candidate prompt.better.txt

기대 출력: 채택

{"verdict": "accept", "current": 0.25, "candidate": 1.0}

3-5GATE일부러 나쁜 수정을 넣어 본다

채택된 지시서에서 규칙 하나(collapse-spaces)를 뺀 후보를 만들어 게이트로 다시 판정합니다.

grep -v collapse-spaces prompt.txt > prompt.worse.txt
python3 miniloop.py gate --candidate prompt.worse.txt
Get-Content prompt.txt | Where-Object {$_ -notmatch "collapse-spaces"} | Set-Content prompt.worse.txt
python miniloop.py gate --candidate prompt.worse.txt

기대 출력: 기각

{"verdict": "reject", "current": 1.0, "candidate": 0.0}
지금 벌어진 일

내 지시서에, 나쁜 수정이 들어오는 걸 막는 장치가 붙었습니다. 누가(사람이든 LLM이든) 무엇을 제안하든, 한 번도 안 본 heldout 점수가 거부권을 쥡니다. 1강에서 이 검문 하나를 껐더니 0.554가 0.026이 됐던 걸 기억하세요.

3-6완주 판정

처음 상태로 되돌린 뒤, 채택과 기각이 둘 다 재현되는지 한 번에 확인합니다.

printf 'strip-checkbox\ncollapse-spaces\nassignee-first\n' > prompt.txt
rm -f trace.jsonl && python3 miniloop.py run >/dev/null && \
python3 miniloop.py gate --candidate prompt.better.txt | grep -q '"accept"' && \
python3 miniloop.py gate --candidate prompt.worse.txt  | grep -q '"reject"' && \
echo "LAB PASSED" || echo "LAB FAILED"
Set-Content prompt.txt "strip-checkbox","collapse-spaces","assignee-first"
Remove-Item trace.jsonl -ErrorAction SilentlyContinue
python miniloop.py run | Out-Null
$a = python miniloop.py gate --candidate prompt.better.txt | Select-String accept
$r = python miniloop.py gate --candidate prompt.worse.txt  | Select-String reject
if ($a -and $r) { "LAB PASSED" } else { "LAB FAILED" }

기대 출력

LAB PASSED
막혔을 때: LAB FAILED가 나온다

3-4와 3-5를 따로 다시 돌려 어느 쪽이 어긋나는지 봅니다. accept가 안 나오면 gate가 train을 채점하는 구현일 가능성이 큽니다 (STEP 2의 검사 ①로 돌아갑니다). reject가 안 나오면 "gate에서 candidate 점수가 현재 점수보다 높을 때만 accept하게 고쳐라"라고 시킵니다.

체크포인트: LAB PASSED가 나오면 루프 한 바퀴 완주. 결과물 ②입니다.

4-1보고서와 검문기를 만든다

AI 도구에 아래를 붙여넣습니다. 보고서(report.md)는 STEP 3 루프의 출력을 정리한 모양이고, 검문기(body_guard.py)는 본문을 꺼내 줄 단위로 대조하는 짧은 코드입니다.

아래 두 파일을 현재 폴더에 UTF-8 인코딩으로 만들어라. 내용은 한 글자도 바꾸지 마라.

=== body_guard.py ===
#!/usr/bin/env python3
"""권한 검문: 서식 노드가 본문 텍스트를 건드렸는지 코드로 확인한다.

사용법: python body_guard.py report.md report.html
본문을 꺼내고, 마크다운 마커를 지우고, 줄 단위로 대조한다. 그게 전부다.
"""
import re
import sys
from pathlib import Path


def md_lines(path):
    lines = []
    for line in Path(path).read_text(encoding="utf-8").splitlines():
        t = line.strip()
        t = re.sub(r"^#+ ", "", t)     # 헤딩 마커 제거
        t = re.sub(r"^[-*] ", "", t)   # 리스트 마커 제거
        t = t.replace("**", "")
        if t:
            lines.append(t)
    return lines


def html_text(path):
    h = Path(path).read_text(encoding="utf-8")
    h = re.sub(r"<style.*?</style>", " ", h, flags=re.S | re.I)
    h = re.sub(r"<script.*?</script>", " ", h, flags=re.S | re.I)
    h = re.sub(r"<[^>]+>", " ", h)
    return re.sub(r"\s+", " ", h)


def main():
    if len(sys.argv) != 3:
        print("usage: python body_guard.py report.md report.html", file=sys.stderr)
        sys.exit(2)
    md, html = sys.argv[1], sys.argv[2]
    text = html_text(html)
    lines = md_lines(md)
    bad = [ln for ln in lines if ln not in text]
    if bad:
        print("FAIL: 본문에서 사라지거나 바뀐 줄")
        for ln in bad:
            print("  " + ln)
        sys.exit(1)
    print(f"PASS: 본문 {len(lines)}줄 전부 그대로")


if __name__ == "__main__":
    main()

같은 AI 도구에 이어서 붙여넣습니다. 파란 줄이 계약입니다.

같은 폴더의 report.md를 읽어, 보기 좋은 report.html 하나로 만들어라.

바꿔도 되는 것은 HTML 구조와 CSS뿐이다.

대부분의 일은 그래프가 필요 없습니다. 한 가지 일에 검증자 하나면 그건 루프입니다. 노드는 검증 방법이 달라질 때만 나눕니다. 내용은 데이터와 대조했고(miniloop), 서식은 렌더를 봐야 했습니다(body_guard). 그리고 방금 그래프는 명령 몇 줄이었습니다. 먼저 그래프를 그리고, 필요해지면 도구를 붙입니다.

체크포인트: FAIL로 잡히고 PASS로 돌아오면 STEP 4 끝. 결과물 ③입니다.

STEP 5

내 업무로 갈아 끼운다

여기까지의 견본 과제는 발판이었습니다. 이제 같은 골격에 내 업무를 넣습니다. 바뀌는 것은 사례와 판정 규칙뿐이고, 검사는 그대로입니다.

5-1새 폴더에서 시작한다

mkdir -p ~/my-loop && cd ~/my-loop
mkdir $HOME\my-loop; cd $HOME\my-loop

5-2내 사례 10개를 모은다

반복해서 하는 업무 하나를 고릅니다. 주간 보고, 회의록 정리, CS 답변 초안, 릴리스 노트. 그 업무의 실제 입력과 만족했던 출력을 STEP 1과 같은 형식으로 적습니다: train 6개, heldout 4개.

expected를 못 적겠다면

expected는 정답 전문이 아니어도 됩니다. 판정 규칙이 볼 것만 있으면 됩니다. 들어가야 할 티켓 ID 목록, 일치해야 할 수치처럼요. 과거에 "이건 아니었다" 싶었던 출력을 세 개 떠올리고, 왜 아니었는지를 적어 보세요. 그 답("숫자가 틀렸다", "항목이 빠졌다")이 판정 규칙이 됩니다.

5-3STEP 2의 프롬프트를 고쳐서 다시 시킨다

STEP 2 생성 프롬프트를 복사해 세 곳만 바꿉니다.

바꾸는 곳무엇으로
[과제]내 업무 한 줄 + 입력→출력 예 하나
[규칙 사전]내 판정 규칙. "완료 티켓 ID가 expected와 전부 일치하면 1점" 같은, 코드로 대조 가능한 문장
tasks.json5-2에서 모은 내 사례 10개

[명령 세 개]와 [불변식]은 한 글자도 바꾸지 않습니다. 어떤 업무에서도 같은 부분입니다.

RUN에 LLM이 필요하다면

견본 과제와 달리 내 업무의 변환은 규칙만으로 안 될 수 있습니다. 그럴 땐 RUN 자리에 과거 출력물을 그대로 넣고 JUDGE와 GATE부터 완성하세요. RUN이 확률적이어도 채점은 결정적이어야 한다는 불변식 2는 그대로 지킵니다. 같은 출력을 두 번 채점하면 같은 점수.

5-4검사는 똑같이 한다

숫자는 달라져도 확인 항목은 STEP 2·3과 같습니다.

확인방법통과 기준
gate가 heldout만 보는가코드를 눈으로gate에 train이 없다
점수가 결정적인가run 두 번완전히 같은 출력
거부권이 작동하는가규칙 하나 뺀 후보로 gatereject

체크포인트: 내 업무 데이터에서 reject 한 번을 보면 끝. 내 지시서에 거부권이 생겼습니다.

마무리

핵심 정리

  1. 루프가 되는 업무는 반복되고, 판정할 수 있고, 실패가 모이는 업무다.
  2. 하네스는 에이전트가 짜고, 나는 같은 세 가지만 검수한다: heldout만 보는 gate, 결정적 점수, 남는 TRACE.
  3. 지시서는 루프가 고치고, 채택은 GATE가 결정한다. STEP 3의 reject가 그 증거다.
  4. 노드는 검증이 달라지는 자리에서만 나눈다. 권한은 사람이 믿는 게 아니라 코드가 확인한다.
  5. 대부분의 일은 그래프가 필요 없다. 먼저 그래프를 그리고, 필요해지면 도구를 붙인다.

다음 반복실습이 끝난 뒤

my-loop의 하네스는 과거 사례로 돌았습니다. 다음에 그 업무를 실제로 다시 할 때는 하네스 안에서 처리하고, 출력을 tasks에 한 줄 보탭니다. heldout은 주기를 정해 갈아 끼우되, 갈아 끼우기 전까지는 열어 보지 않습니다.

FAQ자주 나온 질문

내 업무는 판정이 거의 다 "느낌"인데요.
그 느낌을 만든 최근 실패 세 건을 적어 봅니다. "왜 아니었지?"의 답은 대개 규칙 문장이 됩니다("숫자가 틀렸다", "너무 길었다"). 그렇게 캐낸 규칙 두세 개로 시작하고, 규칙이 못 보는 부분은 그래프의 마지막 육안 노드로 남깁니다. PASS는 하한선이고 그 위는 사람 몫입니다.
견본 과제가 내 업무랑 너무 다른데, 이게 왜 도움이 되나요?
견본에서 배운 건 과제가 아니라 골격입니다. run/trace/gate 명령 세 개, train/heldout 분리, 인수 검사 세 가지. STEP 5에서 확인했듯 과제를 통째로 바꿔도 이 골격과 검사는 한 글자도 안 바뀝니다. 새 업무를 만날 때마다 이 페이지의 STEP 5만 다시 하면 됩니다.
LangGraph 같은 프레임워크를 배워야 하나요?
STEP 4의 그래프는 명령 몇 줄이었습니다. 프레임워크는 재시도·병렬·체크포인트가 손으로 감당이 안 될 때 가져옵니다. 먼저 그래프를 그리고, 필요해지면 도구를 붙입니다.
하네스를 팀에 어떻게 퍼뜨리죠?
지시서(prompt.txt)와 tasks가 이미 파일이므로 저장소에 올리는 것부터 시작합니다. 동료의 실패 사례가 tasks에 쌓이는 순간부터 팀의 루프가 됩니다. 단, heldout 관리자는 한 명으로 정합니다. 모두가 heldout을 들여다보면 그건 더 이상 heldout이 아닙니다.
